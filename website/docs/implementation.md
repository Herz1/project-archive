实现日期：2026-10-30。范围为 Herz1 本人拥有的全部公开仓库，当前 14 个、5 类，其中 1 个 Fork、2 个真正的空仓库。未发现需追加的组织。没有略去资源、学习或初始记录，也没有以虚构项目填满阵列。

## 从原程序继续

入口“进入档案”保留完整 Rhine 开场；开场按原轨迹进入第一份档案详情，未擅自缩短。项目名牌和手机中的项目链接以数字仓库 ID 直达对应详情。两套框架与 Three.js 版本分路由运行，避免把两套全局 CSS 强行混合。

`scripts/report-preservation.mjs` 根据原始文件与工作副本的实际内容生成 [逐文件复用报告](preservation-report.json)。报告区分逐字节相同、仅 CRLF/LF 不同、适配和未复制；这不是代码行数比例，也不将额外文件计作“原样”。Rhine 未复制的是 40 份原作设定档案 TXT，已由真实项目导出替代；Eidolon 未复制的是不适用的账号应用路由、代理和原分享图等。核心光效、时间线和模型均来自原代码。

不可变原始层另由清单校验：1,506 个文件、58,622,726 字节，仍对应两个固定提交，未修改。工作副本的新增和适配不会覆盖该层。

## 数据与内容

外部元数据和人工展示字段分别保存，原始 GitHub 数字 ID 不随排序改变。P-001 等个人档案编号由人工稳定绑定。查询、收藏、列表和分享地址均使用稳定身份。

公开状态通过 GitHub 公共 REST 接口分页同步；每次推送或手动发布时刷新。对 `size: 0` 额外查 commits API，不把四舍五入为 0 KiB 的 README 仓库误认为空仓库。失效或空的 API 响应不覆盖现有快照。Token 只用于构建过程，不写入页面。

人工说明依据公开 README 和文件信息：MV 仓库按音频与歌词记录，JRPG 按制作工程，达妮娅按已编译发布包归档，鹈鹕杯按初始记录；不夸大为已完成应用。Fork 明确标记，上游主页不作为个人演示。演示地址只从已核对的人工字段提供。

## 实测

- 两套原始依赖锁安装、Next 静态导出、Vite TypeScript 及生产构建通过；组合静态站的 GitHub Pages 子路径资源可访问。
- 8 项自动检查通过：完整收录、排序后身份稳定、自动新增和空类移除、排除私有/外部/重复身份、零大小 README 判断、不同列长循环导航、标准链接和转义、构建路由与资源。
- 4 项字体覆盖检查通过；Noto Sans/Serif 新字形、首屏子集和原 Shippori 拉丁字形保持自托管。普通构建无需下载字体。
- 原始工作副本生成与覆盖保护 2 项检查通过，1,506 文件源快照校验通过。
- 浏览器实测 1440×1000 与 390×844：首屏、分光、14 项光谱、手机滑动入口、浮岛、完整开场到第一份详情、详情到阵列、快速打开/关闭、检索、收藏和真实源码/演示入口。
- 手机导航未遮盖品牌，无横向溢出；详情解密结束后文本恢复可读，原滚动面板可继续查看操作区。
- 减少动态模式使用原 still 布局；无 WebGL 使用原 static 光谱，档案失败时有完整目录入口；关闭 JavaScript 的目录仍有 14 个项目及 14 个标准源码链接。
- 新上下文完整浏览光谱、手机、浮岛和档案，未出现页面运行异常或失败资源请求。修复了上游缺少体素素材时先拒绝 Promise、之后才接回退所产生的未处理异常，仍绘制原有颜色方块和名字。
