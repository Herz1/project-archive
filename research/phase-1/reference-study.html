03 / CODE UNDERSTANDING

可迁移的实现方法

重点看状态、数据、渲染和排版之间如何配合。按相应职责重新实现，更容易适配你的项目规模。

代码位置实现要点迁移到个人首页
Rhine main.tsboot / archive / detail 三种模式；DOM 内容与场景连接；检索、设置及独立查看器有各自入口。建立目录 / 项目详情 / 预览的清楚状态，详情关闭后保留筛选、滚动位置和触发点。
Rhine ui-transitions.ts过渡读取当前透明度与位移；revision 避免旧回调覆盖新状态。弹窗默认 300ms 进入、200ms 退出，正文 150ms。连续开关、快速换项目时接续当前状态；退出动画完成再移除内容，减少动态效果时直接收束。
Rhine appearance.ts
scene.ts		阵列采用实例化；抽取与清晰度在同一物件上连续变更。材质涉及 transmission、roughness 与自定义 shader。三维限定于精选项目的展示区，目录仍用平面文本和图片。先确保内容可用，再决定是否承担这份渲染成本。
Rhine content/README.md内容独立于 TypeScript，页面与 TXT 共用同一份 JSON；当前校验明确限定五个分类、每类八份、合计四十份。内容分离保留，固定数量规则重写。支持任意项目数量、空分类、缺失 Demo、Fork 与归档状态。
Rhine viewport-layout.ts桌面逻辑舞台与窄屏 CSS 像素布局分开；镜头按视口重新取景。手机使用纵向详情和真实可读字号；不能只把桌面布局整体 scale 缩小。
Eidolon Landing.tsx标题、文案、颜色、分组在服务端准备；DOM 标记各幕，客户端接收少量结构化数据。静态构建时就输出身份介绍、项目摘要与链接，避免等 GitHub API 和 WebGL 才能看到内容。
Eidolon LightStage.tsx
stageStore.ts		单一 requestAnimationFrame 推进滚动、纯模型、DOM 样式及绘制；只在当前幕、组合等离散状态改变时通知 React。连续动效走 CSS 变量或渲染循环；不把每帧位置都写入组件状态，避免整页无效更新。
Eidolon model/timeline.ts以“滚过多少屏”为时间单位；sticky 舞台的高度和画面状态共用时间线。仅为短开篇或少量精选建立时间线。全部项目目录使用正常文档流，并提供直接锚点。
Eidolon model/tier.ts
canvasStage.ts		full / lite / basic / reduced / static 五档；优先考虑省流量、WebGL、减少动态和触屏。场景提前约一屏加载，远离时停绘并按条件释放。至少实现完整、轻量、静态路径；帧慢或上下文丢失时保留项目内容。局部效果失败不应拖垮整页。
Eidolon layout.tsx展示字体自托管；首屏字集与其余字集分离，只预载首屏；展示页面有自己的根布局。复用字体加载原则，重新覆盖你的姓名与动态项目名。原站精简字库不一定包含你的新文字。
Eidolon model/color.ts基础色保持稳定，在 OKLab 中派生光晕、深底和可读文字色；算法在服务端运行。分类色建立一组派生 token，正文颜色独立控制；暗蓝等分类不直接拿原色做黑底小字。
Eidolon LandingEntry.tsxhover / focus 时预取面板，点击后才挂载。页头入口与结尾入口共用逻辑。可用于“项目详情”资源的意图预取；普通源码和 Demo 仍提供标准链接。
一个关键边界：展示演示不等于后台能力。Eidolon 未登录页的来电展示，源码会在接听后播放预设开场白与字幕；本次没有进入真实语音会话。你的首页可以展示项目交互样例，但每个样例应清楚说明它演示什么。依据：Call.tsx。

动效要响应最新操作

Rhine 的编号与标题使用约 460ms 的滚动配置；Eidolon 的模型与循环分离。值得保留的是“可中断、无过期回调、快速输入不排队”的行为。

04 / REUSABLE SYSTEM

为你的首页归纳的规范

以下全部是第二步建议。保留可辨识的风格，同时让内容、数量和访问路径适合你的真实仓库。

视觉规则

  1. 一个主隐喻：每个项目是一份成果档案；分类线索可从光束过渡为目录刻度。
  2. 两个明暗场景：深色开篇建立氛围，暖灰目录便于阅读；边界有清楚转场，字体与字段语言保持连续。
  3. 三层字体：展示标题、项目标题/正文、元数据。长项目名保持横排；竖排只用于简短章节装饰。
  4. 颜色有含义：分类色稳定；活跃项才发光。状态同时有文字，不能只靠颜色区分。
  5. 材质有范围：玻璃和透视只出现在少量展示物件；搜索、筛选、长正文使用稳定平面。

交互规则

  1. 首屏可直达全部项目：入口与介绍同时出现；短开篇不锁定滚动，也不要求完成“身份验证”。
  2. 预览与打开分工：hover / focus 可以预览，点击或 Enter 明确打开；触屏有同等可用的入口。
  3. 标准链接可直接访问：源码、Demo、文档均用真实 URL；支持复制、另开标签和浏览器返回。
  4. 详情返回保留上下文：保留筛选、排序、目录滚动；Esc 关闭弹层并归还焦点。
  5. 减少动态仍完整：改为纵向静态排版；无 WebGL 也能浏览全部内容。声音默认静音，只有访客主动开启才播放。

用数据驱动全部项目

建议在构建阶段分页同步已确认账号的公开仓库，生成静态项目快照，再用人工配置补充精选顺序、展示名、分类、截图与更友好的介绍。以 GitHub repository id 为稳定标识，避免改名或排序后详情、收藏指错项目。

“全部”的暂定范围是目标账号下的公开项目，Fork 与归档保留标记和查询入口；组织项目与其他归属需要结合你的实际账号核对。私人仓库不会因“全部项目”被自动公开。抓取失败时保留最后成功快照并展示真实同步时间。

  cover、demoUrl、myContribution、highlights

  缺失字段有明确回退；统计、名称和链接不由动画层编造

实现建议

可用 Vite + TypeScript + CSS，静态构建可读项目正文，再用轻量 DOM 逻辑实现筛选与详情。Three.js 仅在确定需要的展示区按需载入。若目标仓库已有 React 等框架，优先沿用现有架构。

分出内容、目录、详情、动效和数据同步的职责，避免把两个参考的完整应用与后台一起移植。
